# Ребілд BlockCraft — як почати

Цей комплект замінює специфікацію v1. Код v1 не викидається: ребілд іде на ньому етапами R0–R9, працююче лишається, суперечне новій концепції — видаляється.

## Що змінилося одним абзацом

Сайт більше нічого не «створює сам»: моди, ресурспаки, шейдери, датапаки, готові збірки й **реальні сервери** приходять з Modrinth (сервери — новий тип Server Projects, березень 2026), скіни — з галереї MineSkin і Mojang за ніком. Демо-серверів і завантаження PNG більше немає. Ядро — **«Моя гра»** (версія + лоадер для всіх, і для гостя), **двигун сумісності** (файл + залежності + конфлікти з поясненнями) і **збірки** з експортом у `.mrpack`, перенесенням на іншу версію та перевіркою папки `mods`. Шлях гравця на кожній сторінці: **знайти → взяти → поділитися**.

## Комплект

| Файл | Навіщо |
| --- | --- |
| `CLAUDE.md` | Правила для Claude Code: стек, команди, порядок роботи, правила джерел, визначення готовності |
| `docs/product.md` | Концепція: проблема, три дії, джерела, сценарії С1–С7, ролі, карта сайту, тема курсової, демо на захисті |
| `docs/tech.md` | Специфікація: архітектура, моделі, API, джерела, двигун сумісності, фронтенд, етапи R0–R9 |
| `docs/PROGRESS.md` | Трекер R-етапів, рішення v1, що лишаються, журнал рішень v2 |
| `START_HERE.md` | Цей файл |

Поки комплект лежить у `_rebuild/` (поза git). Етап R0 сам перенесе його на місце, а старі документи — в `docs/archive/v1/`.

## Перший запуск

1. Закрий інші сесії Claude Code в цьому проєкті.
2. У папці проєкту: `claude`.
3. Встав перше повідомлення (нижче) і дочекайся плану R0.
4. Далі цикл: `/next-stage` → план → «ок» → реалізація → перевір руками те, що в звіті → `/commit` → `/clear`.
5. Кінець етапу: «Продуктова перевірка етапу» (скріншоти й опис для гостя) → «Запусти code-reviewer по змінах етапу» → виправити → злити гілку етапу в `rebuild`.

## Перше повідомлення для Claude Code

```text
Починаємо ребілд BlockCraft Ukraine (v2).

Нова концепція й специфікація лежать у `_rebuild/` (ще не в git): `CLAUDE.md`, `START_HERE.md`, `docs/product.md`, `docs/tech.md`, `docs/PROGRESS.md`. Прочитай їх повністю зараз, один раз. Далі працюй за новим `_rebuild/CLAUDE.md` (а не за старим кореневим): `tech.md` читай лише потрібними розділами.

Суть змін: контент більше не створюється на сайті — жодних завантажень скінів, демо-серверів і демо-модів. Усе береться з джерел: Modrinth API v2 (моди, ресурспаки, шейдери, датапаки, модпаки), Modrinth API v3 (сервери), MineSkin (скіни), Mojang (скін за ніком). Ядро — «Моя гра» + двигун сумісності + збірки з `.mrpack`. Шлях гравця: знайти → взяти → поділитися.

Зараз — лише етап R0 (tech.md, розділ 13):
1. R0.1–R0.2: збережи незакомічені зміни етапу 10 комітом у `stage-10-packs` (без `_rebuild/`), створи гілку `rebuild`, перенеси комплект на місце, v1-документи — в `docs/archive/v1/`. Кожну git-команду, що змінює історію або файли, спершу покажи мені.
2. R0.3: аудит — `docs/rebuild/audit.md` (модуль → лишити / переробити / видалити → етап R) і скріншоти поточного UI. Потім зупинись і чекай мого «ок».
3. R0.4–R0.5 — після мого «ок», по одній задачі через `/next-stage`.

Якщо щось у специфікації суперечить реальному коду чи реальним відповідям API — не підганяй мовчки: скажи мені й запропонуй рішення для журналу.
```

## Повідомлення на початку кожного нового етапу

```text
Етап R<N>. Прочитай docs/product.md (сценарії, які зачіпає етап), розділ R<N> у docs/tech.md і docs/PROGRESS.md. Створи гілку rebuild-r<N>-<назва> від rebuild. Покажи план усього етапу: задачі, моделі й міграції, ендпоінти, тести, що побачить гість. Чекай «ок», далі — по одній задачі через /next-stage.
```

## Як тримати якість цього разу

- **Не женіть етапи на автопілоті.** v1 пройшов 9 етапів за два дні, і продуктові рішення ніхто не перевіряв. Після кожного етапу сам відкрий сайт і пройди сценарії з `product.md`: чи зрозуміло, навіщо ця сторінка, що тут взяти, що опублікувати.
- **Червоні прапорці** — зупиняй Claude, якщо він пропонує: «тимчасово завантажимо PNG», «додамо демо-сервер», «візьмемо назви полів з документації» без фікстури, «поки вимкнемо тест».
- **R1.2 (`docs/sources.md`) і R0.3 (аудит)** — два місця, де треба прочитати уважно: від них залежить усе інше.
- **R4.3** — перевір `.mrpack` руками в Prism Launcher або Modrinth App. Це найважливіша демонстрація на захисті.
- **Одна задача — одна сесія**, між задачами `/clear`.
- **Повторює помилку двічі** — додай правило в `CLAUDE.md` або `.claude/rules/`.
- Особисті нотатки (тестові акаунти, адреса сервера) — у `CLAUDE.local.md` (він уже в `.gitignore`).
