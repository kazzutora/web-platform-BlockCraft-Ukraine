# Як почати розробку BlockCraft з Claude Code

Цей набір — каркас для Claude Code: правила проєкту, специфікація з етапами й готові команди. Коду ще немає — Claude Code напише його етап за етапом.

## Що в наборі

| Файл | Навіщо |
| --- | --- |
| `CLAUDE.md` | Правила проєкту: стек, команди, порядок роботи, визначення готовності. Claude Code читає його в кожній сесії |
| `docs/tech.md` | Технічна специфікація: архітектура, моделі, API, інтеграції, 19 етапів із задачами й критеріями готовності |
| `docs/PROGRESS.md` | Трекер задач і журнал рішень — Claude Code відмічає тут прогрес |
| `.claude/settings.json` | Дозволи: що Claude Code робить без питань, про що питає, що заборонено (`.env`, `push --force`, `rm -rf`) |
| `.claude/rules/backend.md`, `frontend.md` | Правила коду, які підвантажуються лише при роботі з відповідними файлами |
| `.claude/skills/next-stage` | Команда `/next-stage` — взяти й виконати наступну задачу |
| `.claude/skills/check` | Команда `/check` — лінтери, типи, тести з виправленням |
| `.claude/skills/commit` | Команда `/commit` — коміт у форматі Conventional Commits |
| `.claude/skills/design-system` | Дизайн-система: токени, шрифти, компоненти, правила верстки |
| `.claude/agents/code-reviewer.md` | Окремий агент для рев'ю наприкінці етапу |

## Перший запуск

1. Встанови Docker Desktop, Git, Node.js 24 LTS (+ `corepack enable` для pnpm), uv і Claude Code.
2. Створи папку проєкту й скопіюй туди **вміст** цього набору (разом із прихованою папкою `.claude`).
3. В папці проєкту:
   ```bash
   git init
   git switch -c stage-00-foundation
   claude
   ```
4. Перше повідомлення в Claude Code:
   > Прочитай CLAUDE.md і docs/PROGRESS.md. Ми починаємо етап 0. Покажи план усього етапу 0, а потім виконуй задачі по одній через /next-stage.
5. Далі цикл для кожної задачі:
   - `/next-stage` → Claude показує план → ти кажеш «ок» → він реалізує й тестує;
   - перевір руками те, що він описав у звіті;
   - `/commit`.
6. Наприкінці етапу: «Запусти агента code-reviewer по змінах етапу», виправ знахідки, злий гілку в `main`, створи гілку наступного етапу.

## Поради

- **Одна задача — одна сесія.** Між задачами роби `/clear`: контекст чистий, Claude не плутається. Усе потрібне він прочитає з `PROGRESS.md`.
- **Режим планування** (Shift+Tab) — для великих задач (моделі, нові розділи): Claude лише планує, нічого не змінюючи.
- **Повторює помилку двічі — додай правило** в `CLAUDE.md` або `.claude/rules/`. Тримай `CLAUDE.md` коротким (до 200 рядків).
- **Особисті нотатки** (твої шляхи, тестові акаунти) — у `CLAUDE.local.md`, додай його в `.gitignore`.
- **Windows:** якщо `next dev` у Docker повільний — запускай фронтенд локально (`cd frontend && pnpm dev`), решту в Docker. Це описано в задачі 0.5.
- **Перевір налаштування:** `/context` показує, які файли інструкцій завантажилися; `/doctor` перевіряє конфігурацію.
- Продуктовий опис і дизайн-макети — у документі «BlockCraft Ukraine — аналіз проєкту»; `tech.md` — джерело правди для коду.

## MVP для курсової

Етапи 0–9 (≈ 12–14 тижнів при 2–3 годинах на день): акаунти, моди, обране й колекції, відгуки й коментарі, скіни, сервери, пошук, головна, модерація, деплой і матеріали для пояснювальної записки. Етапи 10–18 — розвиток для портфоліо.
