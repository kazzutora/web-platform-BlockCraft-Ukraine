## Інструкції

1. **Визнач задачу.** Якщо передано аргумент (`$ARGUMENTS`) — це ID задачі. Інакше візьми першу невідмічену задачу поточного етапу з прогресу вище.
2. **Прочитай контекст.** У `docs/tech.md` прочитай розділ цього етапу й лише ті довідкові розділи (моделі, API, інтеграції, задачі), на які задача посилається. Переглянь наявний код, який вона зачіпає.
3. **Перевір готовність.** Якщо є незакомічені зміни, не пов'язані з задачею, — повідом мене й зупинись.
4. **План.** Якщо задача зачіпає більше 3 файлів або змінює моделі чи API — покажи короткий план: файли, моделі й міграції, ендпоінти, тести, що побачу в UI. Чекай мого підтвердження. Запитуй лише те, що справді блокує.
5. **Реалізація** малими кроками в порядку: моделі + міграції → сервіси + тести → API + тести → `make api-types` → фронтенд.
6. **Перевірка.** Запусти `make lint`, `make typecheck`, `make test`. Виправ помилки; якщо після 3 спроб щось не вдається — зупинись і опиши проблему.
7. **Прогрес.** Відміть задачу в `docs/PROGRESS.md`, онови «Зараз». Якщо відійшов від `tech.md` — додай запис у «Журнал рішень» і онови `tech.md`.
8. **Звіт** (коротко): що зроблено; як перевірити руками (URL, кроки); що не увійшло; яка задача наступна. Запропонуй `/commit`, але не комітай сам.
